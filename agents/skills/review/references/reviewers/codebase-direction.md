# codebase-direction

Run only for `codebase`, `next`, roadmap, or improvement-audit mode.

Look for high-leverage future work grounded in repository evidence:

- repeated manual workflows the project could absorb
- stated-but-undelivered README/docs/roadmap promises
- adjacent capabilities made cheap by existing architecture
- major friction visible in setup, tests, architecture, or issue patterns
- consolidation opportunities that improve locality and leverage
- baseline gaps that block safe future work, such as no tests or broken verification

Return 2-4 direction candidates max. Each needs evidence, tradeoffs, coarse effort, and why now. Do not produce generic product ideas. Do not rank feature ideas against bugs/security findings; keep them separate.
